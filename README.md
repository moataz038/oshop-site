# Oshop — وكيل التسوق والشحن الذكي

هذا المستودع هو الحزمة الإنتاجية الحالية لموقع **Oshop**، وكيل الذكاء الاصطناعي المساعد للتسوق والشحن داخل ليبيا.

- الموقع الإنتاجي: <https://oshop-ly.vercel.app>
- مشروع Vercel: `oshop-ly`
- المستودع: `moataz038/oshop-site`
- الواجهة: العربية، اتجاه RTL
- العملة التشغيلية: الدينار الليبي

## خريطة الكود

لشرح وظيفة كل ملف ومسار وقاعدة تعديل آمنة، راجع [docs/CODE_MAP.md](docs/CODE_MAP.md). ولخطوات المساهمة راجع [CONTRIBUTING.md](CONTRIBUTING.md).

## بنية المشروع

```text
vercel-output/
├── static/                         # الواجهة الجاهزة للنشر والملفات الثابتة
│   ├── index.html                  # نقطة دخول HTML
│   ├── admin-login.html             # دخول الموظفين بجلسة HttpOnly
│   ├── assets/                     # JavaScript وCSS والحزم المرئية
│   ├── img/                        # شعار Oshop والرسومات المستخدمة
│   ├── emoji/                      # رموز الواجهة
│   └── flags/                      # أعلام الدول المستخدمة في المقارنات
├── functions/api.func/index.cjs    # API ووكيل الذكاء الاصطناعي وأدوات التسعير
├── functions/api.func/admin-security.cjs # مصادقة الإدارة وحدود API والتحقق
└── functions/api.func/shared-store.cjs # Redis دائم للسجلات والإعدادات وحدود المعدل

tools/
├── product-matching.cjs            # قواعد مطابقة نتائج المنتجات
├── product-matching.test.cjs       # اختبارات المطابقة
├── apply-product-matching-v3.py    # تحديث قواعد المطابقة في حزمة API عند البناء
├── apply-security-hardening.py     # تركيب حماية الإدارة والرؤوس الأمنية
├── apply-shared-storage.py         # توصيل الحزمة بمخزن Redis المشترك
├── security-hardening.test.cjs     # اختبارات المصادقة والمدخلات وحدود API
├── shared-store.test.cjs           # اختبارات REST وLua والتزامن في Redis محلي
├── verify.sh                       # فحص سريع قبل النشر
└── build.sh                        # تحقق وبناء حزمة Vercel الجاهزة
```

`vercel-output` هو المخرج الجاهز للنشر في المشروع الحالي. ملفات JavaScript داخله مضغوطة لأنها ناتج بناء الواجهة؛ لا تعدّلها يدويًا إلا عبر سكربت موثق ومختبر، ثم شغّل `tools/verify.sh`.

## الهوية والمساعد

الموقع يستخدم مساعدًا واحدًا فقط:

- الاسم الظاهر: `Oshop`
- الوصف: `وكيل الذكاء الاصطناعي المساعد`
- مفتاح إعدادات الواجهة: `oshop_prefs`
- الشعار: `vercel-output/static/img/oshop-mark.png`

أي إعداد قديم محفوظ في متصفح العميل يتم ترحيله تلقائيًا إلى مساعد Oshop بدل التسبب في انهيار الواجهة.

## الميزات الحالية

- محادثة وكيل التسوق والشحن باللغة العربية.
- البحث والمقارنة بين الأسواق والمواقع المدعومة.
- مطابقة صارمة لنوع المنتج والماركة والصفات الجوهرية قبل عرض النتائج.
- حاسبة سلة SHEIN داخل الوكيل، وقراءة روابط السلة المشتركة عبر Omkar API.
- حساب التكلفة بالدينار الليبي وفق قواعد الشركة.
- إرسال الطلب إلى واتساب فرع مصراتة أو طرابلس.
- صفحة تتبع الطلبات والإعدادات والملف الشخصي.
- تصميم متجاوب للهاتف والآيباد واللابتوب.
- دعم الوضع الداكن وتفضيلات الواجهة الموجودة مسبقًا.

## التشغيل والتحقق

من جذر المستودع:

```bash
bash tools/verify.sh
bash tools/build.sh
node --test tools/product-matching.test.cjs
```

`tools/build.sh` يطبق تحديث المطابقة والحماية والتخزين بصورة قابلة للتكرار، ثم يفحص الحزمة والإعدادات ويشغّل اختبارات وحدات وruntime. يختبر اختبار runtime الحزمة عبر عمليات منفصلة وخادم Redis Lua محلي؛ إن كانت ثنائيات Redis غير متاحة، يعلن Node عن الاختبار كـskipped ولا يعد ذلك تحققًا كاملًا للحماية المشتركة. راجع [دليل الحماية](docs/SECURITY.md) لمسارات أدوات الاختبار وسقف الخدمة المجانية. رسالة `already patched` طبيعية وآمنة.

## النشر

النشر يعتمد على `vercel.json` ويستخدم `vercel-output` كمخرج جاهز:

```bash
vercel deploy --prebuilt --prod
```

أو اترك GitHub/Vercel ينفذ النشر التلقائي بعد دفع commit إلى `main`.

قبل النشر يجب التأكد من:

1. نجاح `bash tools/verify.sh`.
2. نجاح `node --test tools/product-matching.test.cjs`.
3. نجاح `node --check vercel-output/functions/api.func/index.cjs`.
4. نجاح فحص JavaScript للواجهة.
5. عدم وضع أي مفتاح API داخل Git أو JavaScript الواجهة.

قبل نشر النسخة المحمية إلى Production، أضف `OSHOP_ADMIN_PASSWORD` بطول 32 حرفًا عشوائيًا على الأقل، واربط Redis REST مشتركًا عبر أسرار `KV_REST_API_URL` و`KV_REST_API_TOKEN` أو زوج Upstash المكافئ. لا تعتمد النسخة عند غياب المخزن أو تخطي اختبار Lua. راجع [دليل الحماية](docs/SECURITY.md) لإعداد الدخول والتخزين وحدود الطلبات، واحصل على إذن مستقل قبل نشر الإنتاج.

## إعدادات البيئة السرية

يحتاج الـAPI إلى أسرار بيئة النشر، منها مفاتيح مزود الذكاء الاصطناعي وخدمة قراءة سلال SHEIN. تحفظ الأسرار داخل Vercel Environment Variables فقط، ولا تكتب في README أو الواجهة أو commit.

## قاعدة الصيانة

أي تعديل جديد يجب أن يحافظ على أسماء المسارات الحالية وميزات الوكيل، ويُنفذ في commit مستقل بوصف واضح. لا تحذف بيانات أو مسارات API لمجرد أنها غير ظاهرة في الواجهة؛ افحص استخدامها أولًا، ثم وثّق قرار الإزالة في commit وREADME.
