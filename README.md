# KB Online Store — وكيل التسوق والشحن الذكي

هذا المستودع هو الحزمة الإنتاجية الحالية لموقع **KB Online Store**، وكيل الذكاء الاصطناعي المساعد للتسوق والشحن داخل ليبيا. تبقى أسماء المشروع ومساراته ومفاتيح التخزين الداخلية كما هي للتوافق؛ التغيير هنا للهوية المرئية فقط.

- الموقع الإنتاجي: <https://oshop-ly.vercel.app>
- مشروع Vercel: `oshop-ly`
- المستودع: `moataz038/oshop-site`
- الواجهة: العربية، اتجاه RTL
- العملة التشغيلية: الدينار الليبي

## خريطة الكود

لشرح وظيفة كل ملف ومسار وقاعدة تعديل آمنة، راجع [docs/CODE_MAP.md](docs/CODE_MAP.md). ولخطوات المساهمة راجع [CONTRIBUTING.md](CONTRIBUTING.md).

## الهوية والمساعد

الموقع يستخدم مساعدًا واحدًا فقط:

- الاسم الظاهر: `KB`
- الوصف: `وكيل الذكاء الاصطناعي المساعد`
- مفتاح إعدادات الواجهة: `oshop_prefs`
- الشعار: `vercel-output/static/img/kb-mark.png`
- حساب إنستغرام: <https://www.instagram.com/kb.online.store>

مفتاح `oshop_prefs` ومعرّف المساعد `oshop` باقِيان داخليًا لتفادي كسر الإعدادات المحفوظة أو المسارات. أي إعداد قديم محفوظ في متصفح العميل يظل يُحمّل إلى مساعد KB.

## الميزات الحالية

- محادثة وكيل التسوق والشحن باللغة العربية.
- البحث والمقارنة بين الأسواق والمواقع المدعومة.
- مطابقة صارمة لنوع المنتج والماركة والصفات الجوهرية قبل عرض النتائج.
- قراءة روابط السلال المشتركة مباشرة من SHEIN عبر قارئ مقتبس من `shein-cart` بترخيص MIT، من دون إنشاء حساب أو استخدام خدمة قراءة مدفوعة. إشعار النسبة والترخيص في [vendor/shein-cart](vendor/shein-cart/NOTICE.md).
- عرض تفاصيل المنتجات والأسعار والألوان والمقاسات المتاحة من SHEIN، مع ترك الكميات فارغة حتى يحددها العميل.
- مراجعة وتعديل كمية كل عنصر متاح محليًا فقط؛ لا يُعرض الإجمالي قبل إدخال الكميات.
- حساب التكلفة بالدينار الليبي وفق قواعد الشركة.
- إرسال الطلب إلى واتساب فرع مصراتة أو طرابلس.
- صفحة تتبع الطلبات والإعدادات والملف الشخصي.
- تصميم متجاوب للهاتف والآيباد واللابتوب.
- دعم الوضع الداكن وتفضيلات الواجهة الموجودة مسبقًا.

في مراجعة السلة، لا تُقبل كميات من رابط المشاركة؛ يدخل العميل كمية كل صنف قبل احتساب أي إجمالي. التحويل إلى الدينار متاح لأسعار USD فقط وباستخدام سعر الصرف الإداري الصالح، ولا تُحوّل العملات الأخرى بهذا السعر. إذا غاب سعر موثوق أو سعر الصرف، لا يظهر إجمالي. التعديل محلي: لا يُحفظ ولا يُرسل إلى SHEIN ولا يغيّر التوفر أو ينفذ شراءً. تظهر بطاقة المراجعة على `kb-online-store.vercel.app` فقط، إضافة إلى مضيفي الاختبار المحليين.

## إدارة عبارات الشارة أسفل شعار KB

لوحة العبارات متاحة فقط عبر `https://kb-badge-admin.vercel.app/`، بدخول خاص ومصادقة جلسة خادم. مسار `/kb-badge-admin` وملفاته وواجهات إدارته تعيد 404 بلا صفحة دخول على مضيفات المتجر والمعاينة، حتى مع إرسال جلسة صحيحة. لا يوجد رابط للوحة في واجهة المتجر، ولا تتاح صفحة الدخول المشتركة أو مسار الموظفين على `kb-online-store.vercel.app`؛ ويبقى دخول الموظفين القديم على `oshop-ly.vercel.app` دون تغيير.

لا تُدار من خلالها إلا العبارات الخمس المتناوبة أسفل الشعار. تبقى في مخزن Redis نفسه منفصلة عن إعدادات المتجر، وتظل الحركة والتصميم كما هما. واجهة العرض العامة `/api/kb/badge-display` لا تتغير. يطبق `tools/apply-kb-badge-host-isolation.py` فصل المضيف بعد رقعة اللوحة؛ وتغطي اختبارات الوحدات وruntime رفض المضيف الخاطئ وانتحال الترويسات وأصل الكتابة، والمصادقة واستمرار النصوص عبر مثيلات الخادم.

## التشغيل والتحقق

من جذر المستودع:

```bash
bash tools/verify.sh
bash tools/build.sh
node --test tools/product-matching.test.cjs
python3 tools/shein-cart-quantity.browser.test.py
```

`tools/build.sh` يطبق تحديث المطابقة والحماية والتخزين بصورة قابلة للتكرار، ثم يفحص الحزمة والإعدادات ويشغّل اختبارات وحدات وruntime. يختبر اختبار runtime الحزمة عبر عمليات منفصلة وخادم Redis Lua محلي؛ إن كانت ثنائيات Redis غير متاحة، يعلن Node عن الاختبار كـskipped ولا يعد ذلك تحققًا كاملًا للحماية المشتركة. راجع [دليل الحماية](docs/SECURITY.md) لمسارات أدوات الاختبار وسقف الخدمة المجانية. رسالة `already patched` طبيعية وآمنة.

اختبار المتصفح يستخدم بيانات سلة مصطنعة ويشغّل الواجهة محليًا عند 390×844 و1440×900؛ يتطلب Playwright وChromium ولا يتصل بـSHEIN أو قارئ السلة.

## النشر

النشر يعتمد على `vercel.json` ويستخدم `vercel-output` كمخرج جاهز:

```bash
vercel deploy --prebuilt --prod
```

أو اترك GitHub/Vercel ينفذ النشر التلقائي بعد دفع commit إلى `main`.

قبل النشر يجب التأكد من:

1. نجاح `bash tools/verify.sh`.
2. نجاح `node --test tools/product-matching.test.cjs`.
3. نجاح `node --check vercel-output/functions/api.func/index.cjs`.
4. نجاح فحص JavaScript للواجهة.
5. عدم وضع أي مفتاح API داخل Git أو JavaScript الواجهة.

قبل نشر النسخة المحمية إلى Production، أضف `OSHOP_ADMIN_PASSWORD` بطول 32 حرفًا عشوائيًا على الأقل، واربط Redis REST مشتركًا عبر أسرار `KV_REST_API_URL` و`KV_REST_API_TOKEN` أو زوج Upstash المكافئ. لا تعتمد النسخة عند غياب المخزن أو تخطي اختبار Lua. راجع [دليل الحماية](docs/SECURITY.md) لإعداد الدخول والتخزين وحدود الطلبات، واحصل على إذن مستقل قبل نشر الإنتاج.

## إعدادات البيئة السرية

يحتاج الـAPI إلى أسرار بيئة النشر، منها مفاتيح مزود الذكاء الاصطناعي وخدمة قراءة سلال SHEIN. تحفظ الأسرار داخل Vercel Environment Variables فقط، ولا تكتب في README أو الواجهة أو commit.

## قاعدة الصيانة

أي تعديل جديد يجب أن يحافظ على أسماء المسارات الحالية وميزات الوكيل، ويُنفذ في commit مستقل بوصف واضح. لا تحذف بيانات أو مسارات API لمجرد أنها غير ظاهرة في الواجهة؛ افحص استخدامها أولًا، ثم وثّق قرار الإزالة في commit وREADME.
