# خريطة كود Oshop

هذا الملف هو نقطة البداية لأي مبرمج جديد على المشروع. يوضح أين توجد كل مسؤولية، وما الذي يمكن تعديله بأمان.

## قاعدة مهمة قبل التعديل

`vercel-output` هو ناتج بناء جاهز للنشر. ملفا `index-6ttDirym.js` و`index-ca6a3825.css` مضغوطان، لذلك لا نضيف تعليقات داخل كل تعبير فيهما؛ التعديل اليدوي داخل bundle صعب المراجعة وقد يسبب شاشة بيضاء. استخدم خريطة هذا الملف والاختبارات، واجعل أي سكربت تعديل صريحًا وقابلًا لإعادة التشغيل.

## منطق شاشة البداية

- يقرأ التطبيق التفضيلات من `oshop_prefs`.
- يقرأ علامة الجلسة `oshop_welcome_seen` من `sessionStorage`.
- عند بداية جلسة جديدة، فتح `/` أو `/chat` يعرض `/welcome` أولًا.
- زر «ابدأ» يحفظ العلامة وينتقل إلى `#/`.
- فتح `/chat` مباشرة في جلسة بدأت سابقًا لا يعيد المستخدم إلى الترحيب.

هذا الفصل بين `localStorage` و`sessionStorage` يمنع أن تختفي شاشة الترحيب دائمًا بسبب بيانات اختبار قديمة، وفي الوقت نفسه لا يقطع جلسة المستخدم بعد الضغط على «ابدأ».

## أدوات الوكيل الخلفي

الأسماء العامة التي تظهر في تعليمات الوكيل هي:

- `compare_markets`: مقارنة المنتجات والأسعار بين الأسواق المدعومة.
- `calculate_shein_cart`: قراءة رابط سلة SHEIN وحساب التكلفة حسب قواعد الشركة.
- `track_shipment`: قراءة حالة الطلب أو التتبع.
- `search_china_suppliers`: البحث عن موردين عند طلبات الجملة.

أي مفتاح API أو token يجب أن يبقى في Environment Variables داخل Vercel. لا تضف قيمة سرية إلى bundle الواجهة أو إلى هذا المستودع.

## قواعد تعديل آمن

1. عدّل ملفًا واحدًا أو مسؤولية واحدة في كل commit.
2. ابدأ باختبار أو أضف اختبارًا قبل تغيير قاعدة التسعير أو المطابقة.
3. شغّل `bash tools/build.sh` ثم `node --test tools/product-matching.test.cjs`.
4. اختبر شاشة `/welcome`، زر «ابدأ»، `/chat`، `/shein`، والإعدادات.
5. لا تحذف مسار API أو ميزة مخفية قبل التأكد من عدم استخدامها في الواجهة أو الوكيل.
6. لا تغيّر اسم ملف bundle أو تضف query إلى رابط module؛ هذا سبق أن سبب شاشة بيضاء في المتصفح.
7. ادفع commit واضحًا، ثم راقب نشر Vercel قبل اعتبار التعديل مكتملًا.

## تحسين الأداء في البحث

مقارنة الأسواق تعمل بالتوازي، ولا تنتظر مصدرًا واحدًا بطيئًا إلى أجل طويل. يتم استخدام ثلاثة أسواق افتراضية مناسبة بدل خمسة، مع مهلة 8 ثوانٍ لكل سوق وذاكرة مؤقتة لمدة دقيقتين لنفس الطلب والأسواق. إذا حدّد الوكيل أسواقًا بعينها، تبقى اختياراته محفوظة ولا تُستبدل. لا تُستخدم الذاكرة المؤقتة مع حاسبة سلة SHEIN حتى تبقى بيانات السلة مباشرة.

## بطاقات نتائج المنتجات

أي طلب واضح لمنتج يجب أن ينتج بطاقة `compare` تحتوي النتائج المتاحة. إذا أجاب مزود الذكاء الاصطناعي نصيًا دون استدعاء أداة البحث، يقوم الخادم بمسار حماية باستدعاء `compare_markets` تلقائيًا بدل عرض جملة بلا روابط. الواجهة تعرض صورة المنتج، أو شعار Oshop كصورة بديلة إذا لم يرجع المصدر صورة، مع السعر والرابط وزر الطلب.

## المسار المباشر لطلبات المنتجات

عند اكتشاف كلمات طلب منتج مثل «نبي عطر» أو «ابحث عن فستان»، ينفّذ `A$` بحث `compare_markets` مباشرة قبل استدعاء النموذج. هذا يمنع الرد النصي بلا بطاقة، ويختار سوقين مناسبين للعطور/الملابس وثلاثة أسواق لباقي المنتجات. المحادثة العامة لا تمر بهذا المسار وتبقى سريعة عبر النموذج.

## تفاصيل سلة SHEIN

نتيجة `calculate_shein_cart` تحتوي `customerSummary` مبنيًا من عناصر السلة نفسها. يعرض كل عنصر برقم مستقل، الاسم، الكود، اللون، المقاس، الكمية، سعر الوحدة، الخيارات، ثم الإجمالي قبل التقريب والإجمالي المطلوب. الرد النهائي يستخدم هذا الملخص بدل الاكتفاء بجملة إجمالية من النموذج.
