# حماية Oshop

## دخول الموظفين

المسارات `/api/staff/*` و`PUT /api/settings` وتقارير `/api/requests/*` تتطلب جلسة موظف من `/admin-login.html`، باستثناء تنزيل عميل يملك رمز تقرير صالحًا. كلمة المرور لا تُخزَّن في الواجهة. تحفظ الجلسة في cookie باسم `__Host-oshop_admin` مع `Secure` و`HttpOnly` و`SameSite=Strict`، وتنتهي بعد ساعتين. تغيير كلمة المرور يبطل الجلسات السابقة. تبقى قراءة الأسعار من `GET /api/settings` عامة.

اضبط سر Production باسم `OSHOP_ADMIN_PASSWORD`، بطول 32 حرفًا عشوائيًا على الأقل. لا تضع قيمته في Git أو الواجهة أو سجل النشر. النطاق الافتراضي المسموح لطلبات الدخول والكتابة الإدارية هو `https://oshop-ly.vercel.app`. عند استخدام نطاق آخر، اضبط `OSHOP_ADMIN_ALLOWED_ORIGINS` كقائمة منشأ كاملة مفصولة بفواصل.

إذا غاب سر الإدارة أو المخزن المشترك، تفشل العمليات التي تحتاجهما مغلقةً برسالة عامة `503`؛ لا توجد عودة تلقائية إلى حماية محلية أضعف.

## التخزين المشترك

تستخدم الطلبات والتفاوض وإعدادات الأسعار مخزن Redis REST مشتركًا بين مثيلات Vercel وعمليات التشغيل الجديدة، بدل مصفوفات داخل ذاكرة Function. إنشاء المعرّفات والسجلات والفهارس وتحديث الحالات والإعدادات عمليات Redis ذرية. تبقى السجلات دون TTL أو حذف تلقائي؛ ينبغي تحديد سياسة احتفاظ ونسخ احتياطي ومراقبة سعة مناسبة مع مالك المتجر. هذه الديمومة تعتمد على بقاء خدمة وقاعدة Redis متاحتين، وليست بديلًا عن النسخ الاحتياطي.

اربط قاعدة Upstash بالمشروع، ثم تأكد من وجود أحد زوجَي أسرار الخادم:

- `KV_REST_API_URL` و`KV_REST_API_TOKEN`.
- أو `UPSTASH_REDIS_REST_URL` و`UPSTASH_REDIS_REST_TOKEN`.

لا تكفِ متغيرات الاتصال TCP وحدها. يجب أن تكون REST URL عبر HTTPS. تحفظ بيانات كل بيئة تحت namespace مستقل `oshop:v1:<VERCEL_ENV>:`؛ لا تشارك بيانات Production مع Preview أو Development. لا تُصدّر هذه المتغيرات إلى الواجهة.

المخزن المرتبط حاليًا على الخطة المجانية بسقف معلن **500,000 أمر شهريًا**؛ تحقّق من لوحة الاستخدام قبل التوسع أو إضافة مناطق قراءة. الإخلاء التلقائي معطّل. عند تعطل المخزن أو بلوغ حد الخطة، تُرفض العمليات المتأثرة بـ`503` بدل فقد السجلات أو إسقاط حدود المعدل بصمت. لا يوجد انتقال تلقائي إلى خطة مدفوعة في الشيفرة. سجلات النسخة القديمة التي كانت داخل ذاكرة Function لا تنتقل تلقائيًا إلى القاعدة الجديدة؛ يجب حفظ أي بيانات متاحة منها قبل استبدال الإنتاج إن كان الاحتفاظ بها مطلوبًا.

ذاكرة نتائج البحث وأسعار الصرف الخارجية تظل cache غير سلطوي؛ أما إعدادات المتجر وسجلات الطلبات والتفاوض فمصدرها المشترك Redis.

## تقارير Excel

رقم الطلب وحده لا يسمح بالتنزيل. يصدر الخادم رمزًا عشوائيًا بطول 256 بت مرتبطًا بطلب واحد وصالحًا ساعة. يُعاد الرمز للعميل مرةً واحدة، بينما يخزن Redis بصمته وموعد انتهائه فقط. لا تتضمن قائمة الطلبات `payload` أو بصمة الرمز أو موعده. يستطيع الموظف التنزيل عبر جلسته أيضًا.

## حدود الطلبات

تُحجز الحصة بعملية Redis Lua ذرية ذات TTL، وتُشارك بين كل المثيلات. لا توجد عدادات إساءة استخدام داخل ذاكرة Function. تُحسب جميع محاولات الدخول، الناجحة والفاشلة، بحد 8 محاولات خلال 15 دقيقة لكل هوية عميل مشتقة بـHMAC؛ ولا تخزن مفاتيح العداد عنوان IP الخام.

حدود الدقيقة للواجهات العامة، لكل عميل ثم إجماليًا:

| الواجهة | لكل عميل | الإجمالي |
|---|---:|---:|
| `POST /api/chat` | 20 | 200 |
| `POST /api/transcribe` | 8 | 80 |
| `POST /api/tts` | 20 | 200 |
| `POST /api/client-log` | 60 | 600 |
| `GET /api/settings` و`GET /api/fx` | 120 | 1200 |
| `GET /api/track/*` | 60 | 600 |
| `GET /api/requests/:id/excel` | 60 | 600 |

تُجمع حصة التتبع والتقارير عبر كل الأكواد والمعرّفات، فلا ينشئ تغييرها حصة جديدة. يرجع تجاوز الحصة `429` مع `Retry-After`. يجب التحقق بعد نشر مأذون من هوية `req.ip` على Vercel؛ يثق التطبيق بوكيل واحد ولا يقرأ ترويسات forwarded يدويًا. حدود التطبيق لا تمنع كل هجمات الشبكة أو البوتات؛ تظل Vercel Firewall والتنبيهات ومراقبة الحصص طبقة تشغيلية إضافية مهمة، وليست مفعّلة بمجرد وجود هذا الكود.

## حماية إضافية

تطبق الحزمة ترويسات HSTS وCSP ومنع التضمين وتخمين MIME وسياسة الإحالة والصلاحيات. تُوحَّد المسارات قبل التفويض وحدود المدخلات لمنع اختلاف القرار بالحروف أو الشرطة الختامية. توجد حدود لعدد الرسائل وأحجام النص والصورة والصوت وتنظيف لسجلات العميل. لا يقبل الخادم ترويسة OIDC من العميل كاعتماد؛ تأتي الاعتمادات من بيئة الخادم فقط. لا تعرض `/api/health` تفاصيل المزودين أو الأسرار.

## الاختبار قبل النشر

شغّل `bash tools/build.sh`. يعيد تطبيق خطوات الحماية والتخزين بصورة idempotent، ويفحص الحزمة والواجهة وملفات الإعداد ثم اختبارات الأمان والمطابقة والمخزن. اختبارات REST الوهمية لا تستدعي مواقع حية. تتضمن اختبارات المخزن تكامل Redis محليًا عند توفر `redis-server` و`redis-cli`؛ يمكن تمرير مساراتهما عبر `REDIS_SERVER_BIN` و`REDIS_CLI_BIN`. لا تستبدل نتيجة skipped اختبار Lua فعليًا قبل اعتماد تغيير منطق التخزين.

لا تنشر قبل إعداد الأسرار وقاعدة مشتركة والتحقق من الاختبارات والحصول على إذن النشر. بعد نشر مأذون، اختبر رفض الإدارة دون جلسة، الدخول الصحيح، القراءة من مثيل آخر، ورابط Excel صالح وآخر منتهي. لا تغيّر أسعار أو حالات بيانات الإنتاج بغرض الاختبار دون طلب اختبار منفصل. لا تُعد هذه الإجراءات ضمانًا مطلقًا ضد جميع الثغرات؛ تحتاج الخدمة صيانة ومراقبة وتحديثات مستمرة.
